# Human Pose Estimation Experiments

[![Python](https://img.shields.io/badge/Python-3.11%2B-3776AB?logo=python&logoColor=white)](https://www.python.org/)
[![Colab](https://img.shields.io/badge/Colab-Open%20Notebooks-F9AB00?logo=googlecolab&logoColor=white)](https://colab.research.google.com/)
[![License](https://img.shields.io/badge/License-MIT-green.svg)](./LICENSE)

This repository is a practical benchmark and analysis workspace for MediaPipe, OpenPose, AlphaPose, and Detectron2. It gives one consistent pipeline for cross-framework comparison, canonical keypoint export, and motion-signal analysis with reproducible artifacts.

## What is built

- **One benchmark contract across four frameworks.** MediaPipe, Detectron2, and OpenPose are
  measured on identical input and settings; AlphaPose stays `not_measured` with a stated reason.
- **One canonical COCO-17 schema for every tool.** Separate index maps cover BlazePose's 33
  landmarks, OpenPose BODY_25, OpenPose's 18-part COCO output, and native COCO-17.
- **Real single-frame inference on one licensed photo.** Three tools resolve 16-17 of 17
  canonical joints on the same image and agree on the pose.
- **A stable CSV/JSON export contract** with fixed columns, so downstream code does not care
  which framework produced a row.
- **Latency benchmarks with captured environment metadata**, regenerated by one command.
- **Joint-angle, smoothing, and angular-velocity features**, plus label-free quality
  diagnostics (missing rate, confidence spread, temporal jitter).
- **CI on every push**: lint, unit tests, markdown link check, and a benchmark
  artifact consistency check.

## Why this repo

Pose frameworks expose different keypoint definitions, confidence semantics, and output formats. Without a canonical mapping and export contract, speed and behavior comparisons are easy to misread.

This repository keeps comparison honest by enforcing shared schema, shared artifact structure, and explicit `not_measured` status whenever a tool cannot be measured in the current environment.

## What you will find here

- Canonical mapping utilities under `src/posebench/keypoints_schema.py`.
- Frame-level exporters with stable columns in `src/posebench/export.py`.
- Feature extraction utilities in `src/posebench/features.py`.
- Benchmark runner with environment capture in `scripts/run_benchmarks.py`.
- Colab-first notebooks for per-tool demos and cross-tool analysis.

## Signal quality diagnostics

`notebooks/03_quality_metrics_without_ground_truth.ipynb` screens an exported keypoint
sequence with no labels at all: missing rate per keypoint, confidence distribution, and
frame-to-frame jitter.

![Quality metrics overview](./assets/readme/quality_metrics_overview.png)

Numbers behind the figure are in
[`results/quality_metrics_summary.json`](./results/quality_metrics_summary.json).

Read the current values as a finding about the **input**, not the tool: the sequence clip
`assets/sample_input_motion.mp4` is a face-tracking test video rather than a full-body clip,
so the overall missing rate sits at 0.83. The diagnostics behave correctly; the clip is the
weak link, and replacing it is tracked below.

## Quick start

### Colab

- Open a notebook from the table above.
- Setup cells clone the repo when needed and install dependencies idempotently.
- Outside Colab the install cells are skipped, so a local runtime keeps the environment
  you built from `requirements-dev.txt` plus the optional framework packages below.

### Local

```bash
git clone https://github.com/sumeyye-agac/human-pose-estimation-experiments.git
cd human-pose-estimation-experiments
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements-dev.txt
```

Validation commands:

```bash
ruff check .
pytest -q
python scripts/check_links.py --skip-remote
python scripts/verify_results_consistency.py
```

### Optional framework dependencies

- MediaPipe

```bash
pip install mediapipe==0.10.14 "numpy<2"
```

- Detectron2 (best effort)
  - Colab or Linux GPU flows can use the official install matrix.
  - macOS arm64 CPU can use `conda-forge` builds.

```bash
conda create -y -n posebench-d2 -c conda-forge python=3.10 detectron2
conda run -n posebench-d2 python -m pip install mediapipe==0.10.14 opencv-python-headless "setuptools<81"
```

- OpenPose
  - The notebook does not compile `pyopenpose`. It downloads the official COCO Caffe
    weights into `.cache/models/` and runs them through OpenCV DNN, which needs no
    extra dependency beyond `opencv-python`.
  - Decoding is single-person argmax over the part heatmaps, without PAF grouping.
  - A labeled synthetic sample is used only when the weights cannot be downloaded.

- AlphaPose
  - Official installs can be fragile in ephemeral Colab sessions and require CUDA.
  - The notebook falls back to a schema/export validation path.
  - Fallback outputs are clearly labeled synthetic and never treated as real inference.

## Output format

All tools are mapped into a canonical COCO-17 subset.

- Schema and mapping details are in [`docs/schema.md`](./docs/schema.md).
- CSV contract includes `frame_index`, `timestamp_ms`, `person_id`, `tool`, `schema`, and per-keypoint `{name}_x`, `{name}_y`, `{name}_confidence` columns.

## Reproducibility and consistency

Benchmark artifacts are generated with:

```bash
python scripts/run_benchmarks.py --tool all
```

Generated artifacts:

- `results/benchmark.csv`
- `results/benchmark.md`
- `results/environment.json`
- `results/benchmark_raw_<tool>.json` for measured tools

`results/environment.json` records Python version, platform, optional GPU probe result, and key library versions for the run.

Method details are in [`docs/benchmark_methodology.md`](./docs/benchmark_methodology.md).

## Honest results policy

- Measured numbers are published only when a real adapter run finishes in the current environment.
- Unsupported or failed tools stay `not_measured` with a clear reason.
- Synthetic fallback outputs are labeled as synthetic and used only to validate pipeline contracts.
- No row is backfilled with guessed latency or FPS.

## Limitations

- AlphaPose is `not_measured` on macOS arm64 CPU because the official install requires
  CUDA-dependent custom ops. Its demo export is a labeled synthetic sample, not inference.
- OpenPose runs through OpenCV DNN with the official COCO Caffe weights, not the native
  `pyopenpose` runtime, so its latency is not comparable to published OpenPose numbers.
- OpenPose decoding is single-person argmax; PAF-based multi-person grouping is not implemented.
- Multi-person identity tracking is not part of the shared export contract.
- Confidence values are not comparable across tools; each framework uses its own scale.
- The latency benchmark uses a deterministic synthetic frame, so it measures runtime cost
  rather than behavior on real content.
- The time-series clip is a face-tracking test video, so full-body joints are missing in most
  frames of `notebooks/02` and `notebooks/03`.
- Numbers are single-machine. Nothing here supports cross-machine comparison yet.

## Future work

- Replace the time-series clip with a licensed full-body video, as already done for the demo
  image. This is the highest-value next change.
- Add fixed real-video benchmark clips alongside the synthetic frame.
- Add standardized runtime presets so results from different machines can be compared.
- Add decode-included and decode-excluded benchmark modes.
- Add multi-person association fields to the export contract.
- Extend the schema with optional 3D landmarks while preserving 2D compatibility.
